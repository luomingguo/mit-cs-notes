Bits, bytes, and integer representation

evergreen CSAPP §2.1–2.3 · updated 18 Apr 2026 · 1,840 words · 9 revisions
#representation #c-language #memory #fundamentals
SUMMARY
  • Integers are fixed-width bit patterns. Arithmetic on them is modular, not mathematical.
  • Two's complement lets one adder circuit serve both addition and subtraction — the price is an asymmetric range.
  • Nearly every C integer bug is a signed/unsigned conversion or an overflow, and both are fully predictable from the encoding.
REQUIRES
Binary and hex arithmetic · basic C types
UNLOCKS
lec02 Floating point · Buffer overflows

1. Bit patterns and words

A modern machine stores everything — source, images, instructions, this note — as sequences of bits. Meaning is not in the bits; it is in the interpretation the program applies to them. The same 32-bit pattern is a signed integer, an unsigned integer, a float, or four ASCII characters depending only on which instruction touches it.

The word size of a machine is the nominal size of a pointer, and it bounds the virtual address space: a w-bit machine addresses at most 2^w bytes. On x86-64 that is 2^{64} bytes of address space, of which current hardware wires only 48 bits.

1.1 Hexadecimal as a reading aid

Hex exists because one hex digit is exactly four bits, so the mapping is memorisable and local — you can translate any window of a byte string without carrying context. Reading raw memory dumps in decimal is a mistake; the digit boundaries no longer line up with anything the hardware does.

2. Two's complement

Unsigned interpretation is the obvious one: every bit contributes a positive power of two. Signed interpretation keeps that rule for all bits except the most significant, whose weight is negated:

B2U / B2T

The consequence worth memorising is the asymmetry of the range, range: there is one more negative value than positive. So -INT_MIN is not representable, and negating it silently returns INT_MIN again. Every "abs() is always positive" bug traces back to this one line.

C · overflow.c copy 
/* Both branches are reachable. Neither is a compiler bug. */
int x = INT_MIN;
if (-x < 0)
    puts("negation of INT_MIN is still negative");

unsigned int u = 0;
if (u - 1 > u)
    puts("unsigned wraps to UINT_MAX");   // modular, well-defined

3. Conversion pitfalls in C

Casting between signed and unsigned of the same width does not touch the bits — it only changes the interpretation function applied to them. The danger is that C applies those casts implicitly: in a mixed comparison the signed operand is converted to unsigned, so a negative length check can pass a bounds test it should have failed.

COMMON CONFUSION
Signed overflow is undefined behaviour; unsigned overflow is well-defined modular arithmetic. These are not the same rule, and optimisers exploit the difference aggressively.
