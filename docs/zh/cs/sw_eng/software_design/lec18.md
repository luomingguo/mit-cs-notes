# Lec 18 价值敏感设计

官方课件：[Value Sensitive Design](https://61040-fa25.github.io/assets/lecture-notes/vsd.pdf)。本讲的核心不是在开发末期"加上伦理"，而是承认每一个设计取舍都在编码优先级；技术被采用之后，又会规模化地反过来塑造人的价值与行为。

本节目标：

- **理解定位** 明白技术从不是"中立"的——每一个设计决定都隐含着对某些价值的取舍
- **掌握框架** 学会用价值敏感设计（*Value Sensitive Design*，VSD）的四个标准分析一个产品的社会影响
- **识别风险** 熟悉 Ethical OS Toolkit 提出的八大风险区，能在设计早期主动排查
- **建立责任感** 理解"负责任的创新"包含"不造成伤害"与"创造正面影响"两个层面，而不仅是避免法律风险

## 技术从不是中立的

**核心问题：技术不仅是"能不能做"，更是"应不应该做"和"会造成什么后果"。**

技术设计会影响社会结构、人类行为、权力关系、民主制度、隐私与自由——技术人员实际上在设计未来社会的运行规则。一个常被引用的例子是 Facebook：它的本意是连接人与人的关系网，但实际效果却包括信息极化、假新闻传播、心理健康影响、干扰民主制度。**技术最大的风险，正是造成设计者没有预料到的意外后果**（*unexpected consequences*）——这也是本课程"软件创新失败模式"里反复出现的主题（参见 [Lec 1](./lec1.md)）。

作为设计者，必须在动手之前就提前追问：这项技术会被滥用吗？谁会因此受到伤害？它的长期影响是什么？

创业者真正设计的不只是产品，而是公司本身——公司的使命、价值观与文化，这些东西反过来决定产品方向、道德准则与社会影响。程序员不是"中立的执行者"：你决定什么被允许、什么被禁止、什么被放大、什么被压制。当你设计推荐算法、排名系统或内容审核系统时，你就在决定哪些声音被听到、哪些声音被忽略。

考虑这些价值不只是道德考量，也是商业考量——它能帮助吸引优秀人才、建立用户信任、避免灾难性的法律诉讼或公关危机、并建立长期竞争优势。但现实中，公司常用一些借口来忽略这些问题："我们还在找 product-market fit""没资源""太早考虑这些""不会发生问题""这不是我们的问题"。

## 价值敏感设计（VSD）的四个标准

**价值敏感设计**（*Value Sensitive Design*，VSD）是一种在设计信息系统时，主动把人类价值纳入设计过程的方法（*an approach to account for human values in the design of information systems*）。其目标是确保设计给直接和间接的利益相关者（*stakeholder*）带来正向价值，同时提前规划、降低负面影响。VSD 提出四个需要同时考察的标准：

### 1. 利益相关者（Stakeholders）

不仅要考虑**直接利益相关者**（直接使用产品的人），还要考虑**间接利益相关者**（因为这项技术的存在而受到影响、却并非目标用户的人）、非目标使用群体、能力差异人群，以及"转手使用"（技术被原始用户之外的人使用）等情况。

典型案例是导航软件的 **"Waze 效应"**（*Waze effect*）：Waze 为驾驶者（直接利益相关者）计算出最快路线，但这条路线可能会把大量车流引导进原本安静的居民区（间接利益相关者），给当地社区带来噪音、安全隐患等负面影响——设计者只优化了直接用户的体验，却把成本转嫁给了没有被征询意见的旁观者。这也呼应 [Lec 1](./lec1.md) 里 Google Glass 因"忽视关键利益相关者"而失败的案例。

**能力差异**（variation in abilities）也是利益相关者分析的重要一环。一个值得警惕的反例是所谓的**"残障小玩意"**（*Disability Dongle*）——由不了解真实需求的设计者主导、为残障群体设计的花哨辅助科技原型（比如某些看起来很酷但并不解决实际痛点的轮椅原型），本质上是在没有真正征询目标用户意见的情况下"替他们设计"。相对的正面案例是**"路缘坡效应"**（*curb-cut effect*）：人行道路缘为轮椅使用者做的缓坡（curb cut），最终让推婴儿车、拉行李箱、送货推车的所有人都受益——为最边缘群体做的无障碍设计，往往能给所有人带来更好的体验，这提示设计者：认真对待能力差异，反而可能扩大产品的价值覆盖面。

### 2. 时间（Time）

这一标准受城市规划长期视角的启发，提醒设计师考虑技术在**新奇阶段过去之后、真正融入社会**时会产生什么长期影响——很多问题只有在技术被广泛采用、成为日常生活的一部分后才会显现。

一个值得纳入时间视角的概念是**主动"不使用"**（*non-use*）：设计不应该只考虑"如何让人用起来"，也应该考虑"是否应该被使用、什么情况下应该被禁止使用"——比如围绕人脸识别技术在公共场所使用的立法争议，正是对"这项技术长期存在是否可接受"的社会性追问。

另一个值得关注的现象是**再挪用**（*reappropriation*）：软件常常是"可塑的"（*malleable*），用户会以设计者完全没预料到的方式使用它——比如用 Excel 的单元格画像素画、用它记录桌游《龙与地下城》的角色卡；又比如 TabFS 这类工具，把浏览器标签页当作文件系统来"挂载"使用。时间维度提醒设计者：产品发布之后的漫长使用周期里，用户会不断重新定义它的用途，好的设计应该为这种"被重新诠释"的可能性留出空间，而不是假设自己一次性定义了产品的全部意义。

### 3. 普及性（Pervasiveness）

普及性标准关注交互技术被广泛采用后产生的**系统性相互作用**。技术可以在地理（如城市导航软件在城市地区的普及）、文化（如短信在聋人社区的交流方式变化）、人口统计（如青少年之间的社交网络使用）等多个维度上变得普及；系统越普及，个体层面看似合理的设计选择，就越可能在整体上产生意料之外的社会性后果。

一个具体例子是**预测文字/自动补全**的演进——从早期 Nokia 手机的 T9 输入法，到今天 Gmail 的 Smart Compose，自动补全让个体写一封邮件的速度越来越快。但当这项技术在所有人身上普及之后，会出现一种**"更多邮件的悖论"**：每个人写邮件更快了，但邮件的社会规范和期待随之改变——大家默认可以更随时地发送和回复邮件，最终导致的是所有人的总邮件量、总沟通负担不降反升。一个只优化"单次写作速度"的功能，在普及之后反而可能加重了整个系统的沟通负担——这正是"普及性"标准要提醒设计者去追问的系统性效应。

### 4. 价值（Value）

价值标准直接关注技术对人类价值观的影响。VSD 文献中对"价值"的定义是："一个人或一群人在生活中认为重要的事物。"设计时必须考虑隐私、公平、匿名性、安全性与尊严等价值，并诚实地面对不同价值之间的冲突（例如便利与隐私的冲突、效率与公平的冲突）——先弄清楚相关群体真正在意什么，识别潜在冲突，再有意识地选择并验证要优先保障哪些价值，而不是假装冲突不存在。

## 负责任的创新

这是本讲最核心的概念，包含两个层面：**不造成伤害**与**创造正面影响**。

前者要求设计者主动避免：暴力与极端主义传播、算法歧视、隐私侵犯、劳动剥削、民主破坏、社会不平等扩大。

后者的目标则更进一步：促进人权、提升教育公平、改善医疗普及性、支持联合国可持续发展目标（SDGs）。

### Ethical OS Toolkit 的八大风险区

《Ethical OS Toolkit》为技术开发者提供了一份用于识别、应对潜在社会风险的清单，划分为八个风险区：

1. **真相、虚假信息与宣传**：虚假信息的传播及其对公众认知和民主制度的影响
2. **成瘾与多巴胺经济**：利用心理触发机制设计的技术导致的成瘾问题
3. **经济与资产不平等**：技术可能加剧已有的经济差距
4. **机器伦理与算法偏见**：AI 与算法决策带来的伦理问题，包括偏见与歧视
5. **监视国家**：政府或公司大规模监视带来的影响
6. **数据控制与货币化**：个人数据的控制权、隐私与商业化问题
7. **隐含信任与用户理解**：用户对技术的误解或过度信任可能导致的误用或伤害
8. **仇恨与犯罪行为者**：个人或群体利用技术实施或煽动有害、非法行为

**可直接使用的分析框架**：

- **Ethical OS**：识别技术风险与社会影响（即上文八大风险区）
- **Consequence Scanning**：系统化思考 best case / worst case / misuse case 三种情形
- **Ethical Data Canvas**：分析数据来源、数据风险、数据偏见
- **社会中心设计（Society Centered Design）**：不是 user-centered，而是 society-centered——把评估范围从单个用户扩大到整个社会
- **设计正义网络（Design Justice Network）**：核心思想是技术必须服务所有人，而不是强化既有的不平等
