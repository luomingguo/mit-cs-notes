# Lec 7 用接口实现时序电路模块

复杂硬件被看作是一些模块的集合，它们的输入/输出线以某种方式连接在一起。这种观点在技术上是正确的，但对设计过程没有太大帮助。“只看连线”的方式太底层、太机械化，不利于从高层抽象出复杂系统的结构，也不利于根据性能和应用需求多次实例化模块，也不利于将IP封装成可直接组合构建大型系统的“黑盒”模块。现代硬件开发大量依赖**IP核（IP blocks， 知识产权核）** —— 例如 CPU 核心、加密模块、DMA 控制器等通用或商业模块。此外，这种做法也缺乏对模块化细化（modular refinement）的支持，使得开发者难以在不了解整个设计的前提下对某个模块进行独立改进。



## 引例：FIFO

通过一个小故事，FIFO的例子来讲解IP核复用的困难点。

> 一个小故事 
>
> 作者曾经经营一家芯片设计公司。有一天，他震惊地发现：同一块芯片上竟然有 26 个 FIFO（先进先出队列）模块，而这 26 个 FIFO 居然来自 23 种不同的设计。他感到非常困惑，于是去询问工程师原因。工程师们回答说：“这个 FIFO 不符合我的需求。”
>
> 作者继续追问：“但它不是 FIFO 吗？”
>  工程师们回答：“是啊，它是 FIFO，但不适合我。”
>
> 这个回答引起了作者的兴趣，他在飞往圣地亚哥的飞机上从网上下载了一个免费的 FIFO 模块来研究。结果第一件让他震惊的事情是：该模块的用户文档有 23 页之多。而这份文档并不是在讲 FIFO 是怎么实现的，而是**讲怎么使用这个 FIFO**！
>
> 这让作者意识到：即使像 FIFO 这么简单的模块，其使用方式也可以非常复杂，使用者需要理解很多细节、信号命名约定（例如 `n` 表示反相信号，低电平表示有效）、时钟和复位信号等。
>
> 文档中还写道：
>
> - 如果在 FIFO 已满时尝试 push 操作，会产生 error。
>
> 如果 FIFO 已满还去 push，文档说“会出错”，但到底怎么出错？是忽略？是丢数据？是溢出？文档并不清楚。有些说明看起来合理，比如“FIFO 为空时不能 pop”，但它说的都是一种“建议”而非明确规范。文档还告诉你，“如果你这么做，内部的 V 指针将在下一个时钟沿上增加”。作者质疑：我只是用户，我不应该知道也不想知道 FIFO 的内部是怎么实现的。这完全**违反了“黑盒”设计原则**：模块使用者应该只关心接口，不该被迫了解内部细节。

本质问题：功能和实现细节耦合了（mix functionality and implementation）。

下面是FIFO的其中一个组件——计数器——的接口。

![image-20250509205104573](https://tc-1258979383.cos.ap-guangzhou.myqcloud.com/681dfa41d5b54.png)

```verilog
interface Counter;
  method Action inc;
  method Bit#(2) read;
endinterface;
```

- 一个module有一个内部状态。
- 内部状态只能由（接口）方法读取和操纵。
- Action指定了哪个状态元素会被更改。
- Action是原子的。

## 流水线技术引入和介绍

非流水线和流水线技术的差别，在于能否同时执行多条指令。

![截屏2024-07-03 18.02.28](https://tc-1258979383.cos.ap-guangzhou.myqcloud.com/6835361ddd632.png)

- 流水线的每个阶段都以相同的时钟速度运行
- 吞吐量： 单位时间内能完成的工作量(at what rate can we produce valid inputs or outputs)
- 时延： 完成一项工作（经过整个系统）的总时间
- 这里的工作取决于应用
  - 如果是一个算术计算函数f，工作就是一个输入数字x，输入是f(x)
  - 如果是处理器，我们说一项工作就是一条指令。但是输出不确定，一定这是比较复杂的设备，所以我们只能说，单位时间能处理多少指令。
- 流水线的概念不仅限于处理器或计算机体系结构中的应用，也可以应用于电子设计中的组合电路和时序电路

## 组合电路的流水线

![截屏2024-07-03 18.23.01](https://tc-1258979383.cos.ap-guangzhou.myqcloud.com/6835361fe26f6.png)

这个电路由3个子模块，F，G，H 以及他们的电路时延，我们称之为传播时延(propagation delay)t_PD, 该组合电路的吞吐量为 1/t_PD

但要注意的是，我们并没有充分利用我们的硬件资源。 F 和 G 在周期开始时完成它们的工作，而 H 则在周期末尾工作。因此，当 H 执行其计算时，F 和 G 完全空闲 – 这并不是我们硬件资源的最佳利用方式。

相反，解决方案是**使用寄存器来保存稳定的输入值**！如果我们保存 F 和 G 的值，那么当 H 在当前输入上工作时，F 和 G 可以开始处理新的输入。这给我们带来了一个2级流水线（因为在时钟周期 j 的输入 X 在时钟周期 j + 2 给出有效输出）。

![截屏2024-07-03 18.29.03](https://tc-1258979383.cos.ap-guangzhou.myqcloud.com/6835361f4f4bc.png)



我们发现的非流水线电路的延迟是45ns，吞吐率为1/45，但是如果我们采用2级流水线，我们在蓝色标记的寄存器存储结果，那么时钟的限制因素是最慢的电路组件，即H的工作。因此，我们可以使用25纳秒的时钟周期，这样延迟是50纳秒（比之前稍差），但吞吐量是1/25（比之前好）！总结来说，通过增加寄存器，我们无法使延迟变得更好，但可以提高吞吐量



**流水线图**

![截屏2024-07-09 14.58.35](https://tc-1258979383.cos.ap-guangzhou.myqcloud.com/6835361f92f19.png)

这些行表示我们所处的不同流水线阶段，列表示不同的时钟周期。基本上，每组输入数据在我们的图中沿对角线向下移动，即使需要两个时钟周期才能通过，我们每个周期都在产生一个新的输出。

> [!IMPORTANT]
>
> 一个**k级流水线**是一个非循环电路，其每条从输入到输出的路径上都有k个寄存器。（例如，一个组合电路是一个0级流水线

通过组合，我们假设每个流水线阶段在其输出端都有一个寄存器，而不是在输入端（我们已经在上面的电路中看到了这一点）。如果寄存器总是在一致的位置，这使得我们可以轻松地将流水线电路组合在一起，同时使用相同的时钟周期模式。正如我们所提到的，时钟周期 t_CLK 需要覆盖最长的寄存器到寄存器路径（这很像顺序电路基于寄存器到寄存器路径的限制）。然后我们写下延迟和吞吐量的方程

> [!IMPORTANT] 
>
> L = K * t_CLK
>
> T = 1 / t_CLK

**错误的流水线**

![截屏2024-07-09 15.06.54](https://tc-1258979383.cos.ap-guangzhou.myqcloud.com/6835361f104f5.png)

这个电路的问题在于，从X开始通过A和C的路径，以及从Y开始通过B和C的路径，各自经过2个寄存器。但是A-B-C路径只有一个寄存器，所以这会在周期之间混淆我们的计算！具体来说，我们会同时将A(Xi+1)和Yi送入B；这就是我们需要小心的地方。

> [!IMPORTANT] 
>
> 所有的输入到输出的路径必须要有相同的流水线寄存器，否则， 这个计算不能有效的拆分阶段。

**画好流水线的方法**

1. 画一条表示流水线阶段边缘的线（轮廓），该线穿过所有输出。这条轮廓的端点称为终端点。

2. 画更多连接这两个终端点的线，确保所有箭头都朝同一方向穿过这些线。

   举个例子

   <img src="https://tc-1258979383.cos.ap-guangzhou.myqcloud.com/683536251a964.png" alt="截屏2024-07-09 16.54.52" style="zoom:200%;" />

   ![截屏2024-07-09 15.12.23](https://tc-1258979383.cos.ap-guangzhou.myqcloud.com/6835362687042.png)P1: t_CLK = max{4+3+8, 4+4, 4+4+2, 5} = 15

   P2: t_CLK = max{4+3, 8+5, 4+5, 4+2+5} = 13

   

3. 为了增加流水线阶段，进一步通过步骤二拆分

   P1 + P2: t_CLK = max{4+3, 8, 4+2, 5} = 8

   在红线穿过线连接的每个地方放置一个流水线寄存器。（因为所有连接都与终端点连接，我们可以保证这样会有一个有效的流水线。）我们可以问为什么没有在左上角4和3号电路元件之间添加另一条线，原因是无论如何tCLK至少会是8纳秒。所以我们已经用我们的三级流水线达到了最大的吞吐量！

4. 对于最快可能的流水线而言，时钟频率通常由是最慢的组件决定

最终我们得到时延L = 3 * 8 = 24ns， 吞吐率为 T = 1/ 8ns

**弹性(Elastic)和非弹性(Inelastic)流水线**



![截屏2024-07-09 17.11.01](https://tc-1258979383.cos.ap-guangzhou.myqcloud.com/68353626250d2.png)

**非弹性流水线**: 使用寄存器分隔流水线阶段; 所有流水线阶段同步移动； 启动和停止同步流水线比较复杂

![截屏2024-07-09 17.11.07](https://tc-1258979383.cos.ap-guangzhou.myqcloud.com/68353626d50f9.png)

**弹性流水线**：使用FIFO（先进先出队列）分隔流水线阶段； 如果输入FIFO不为空且输出FIFO不满，则一个阶段可以处理数据。一个阶段可以独立处理数据，只要其输入FIFO不为空且输出FIFO不满。这种方式允许每个阶段独立工作，不必与其他阶段完全同步。弹性流水线的优点是更加灵活，能够更好地处理不均匀的数据流，并且可以在阶段间存在一些延迟，而不会影响整体的处理效率。

举一个例子说明

![截屏2024-07-09 17.24.52](https://tc-1258979383.cos.ap-guangzhou.myqcloud.com/68353627f2842.png)

错误同步流水线, output = h( f(x_i), g(x_{i+1}) )， 这意味着输出取决于两个不同时间点的数据。这与同步相违背。

假设FIFO B 在最开始是空的，用一个规则来描述这个电路永远不会启动。

> [!IMPORTANT]
>
> 规则： 
>
> B.any(f(A.first)) ： 是FIFO B 可以接受来自 A 的第一个元素经过函数 f 处理后的数据
>
> C.any(h(g(A.first),B.first))： 意思是 FIFO C 可以接受通过函数 h 处理后的数据，这些数据是来自函数 g 处理过的 A 的第一个元素和 B 的第一个元素
>
> A.deque, B.deque: 意思是A和B都会从队列中弹出数据

原因分析： 在初始状态，B 是空的，所以 B.first 不存在。
需要 B.first 和 g(A.first) 才能使 C 接收数据。B 可以接受 f(A.first)的数据，但是需要满足某些条件使其开始工作，例如 A 必须有数据且 B 必须准备好接收。

### 前馈流水线

我们现在讨论的都是前馈流水线，因为它没有任何feedback， 但是时序电路允许有反馈。为什么组合电路不能有？ 因为这样会无限循环。 前馈流水线的好处是容易插入流水线阶段以及保留功能。

通过在反馈路径中插入 FIFO，可以轻松改变带有反馈环路的流水线的功能

对带有循环的模块网络进行流水线处理需要仔细分析流水线的预期功能

**分析困难在于模块的接口不表明模块是否内部流水线化或是否按顺序处理项目**：模块的外部接口通常只描述了输入和输出的数据格式和接口，而不清楚模块内部的具体实现细节，增加了对流水线行为和性能影响的分析难度。
