## 为什么会探索微内核？ 

>  内核应该做什么事？

不同的人有非常不同的主观偏好，他们喜欢在什么样的基础设施上编程。对于传统的方法，即宏内核，意味着内核是一个单一的大程序，它可以在同一个程序做各种各样的事情，事实上，这确实反映了人们对内核应该做什么的想法。像 Linux 这样的内核的一个特点是，它们提供了强大的抽象，他们选择像文件系统这样的东西，这是一个复杂的项目，它们提供文件系统，文件、目录和文件描述符作为它们的接口，而不是将磁盘硬件作为它们与应用程序的接口。另一个例子是，Unix Linux 提供了地址空间抽象。而不是提供一些东西，而不是提供对 MMU 硬件的直接访问。

> 那宏内核有什么优缺点？

这样做的**好处**是：

- 对于应用开发者
  - 获得可移植性的方法
  - 对应用程序隐藏了复杂性
- 对于内核开发者
  - 获得可移植性的方法
  - 容易构建抽象，体现在
    - 所有不同的内核子系统，比如文件系统，内存分配器，调度器以及虚拟内存，它们都是一个大的程序的一部分但是在宏系统中，只有一个大程序
    - 所有代码都以完全硬件权限运行，比如，所有 xv6 都在管理员模式下运行，这意味着没有限制

这样做的**缺点**：

- 代码庞大， Linux 在几十万到几百万行代码之间，难以维护
- bug，和安全问题
- 通用意味着缓慢，对于特定的东西并不是最优
- 可扩展性问题。让程序能够在运行时修改内核，能够下载内核中的新代码，或者改变它的运作方式之类的，为了能让数据库能够控制磁盘上的数据布局
  - 宏内核没有任何特定的功能，来帮助这种扩展能力，只是困在内核中了

“千呼万唤始出来”，时至今日，今天特别受欢迎的一个，这就是微内核的想法。可能从 20 世纪 80 年代中后期开始。最重要的想法是，顺便说一下，微内核这个词指的是一种一般的方法，一个概念，它不是任何特定的东西，有许多人设计和构建操作系统，根据微内核的一般方案，但是，这些项目最终设计和操作系统都可能有很大的不同。





## 微内核介绍

### 关键思想

关键的想法是微小的内核，仅支持 IPC 进程间通信，以及某种线程或任务的概念。所以，你有一个内核，它为你提供一种类似于抽象的进程的概念，进程之间可以互相通信，通过这种进程间通信，没有其他的了。其他你可能想做的事，比如要实现的文件系统，作为进程或任务在用户级代码，而不是在内核中。

![image-20240908170831891](https://tc-1258979383.cos.ap-guangzhou.myqcloud.com/66dd69a294c41.png)



实际上，今天仍在使用一种微内核， L4 微内核。有很多 L4 实例运行，微内核优势在小型嵌入式专用计算机系统中，不是笔记本，而是专用于单一专门任务的计算机，不需要 Linux 的复杂性。比如说

1. 因为它被用在很多手机里，在小型控制器上控制手机无线电
2. 而且它也被用于最近的 iPhone ，作为 iPhone 上的专用 enclave 处理器上运行的操作系统，用于隐藏密钥

微内核的另一种最终结果是，用户级服务与其他程序通过 IPC 与它们交互，也已经进入了很多操作系统，就像 Mac OS ，它既是一种普通的宏内核，它还很好地支持用户级服务，以及 Unix 进程之间与服务交互的 IPC 

> 为什么微内核有吸引力？

- 高层次而言，这是一种审美，很多人都觉得像 Linux 内核这样庞大复杂的单一程序，并不是很优雅
- 更小的内核可能更安全，代码越少， bug 越少，更少有人利用其中的 bug 来破坏安全
  - 一个被证明是安全的操作系统， seL4，它是 L4 微内核的众多后代之一
- 少量代码通常更容易优化
- 小内核可能会产生更少的设计决策，让应用程序员自己想办法，因此，它提供了灵活性
- 通过构造用户级别的服务
  - 让代码更加**模块化**，也就是说更容易调整，替换或修改，或者说定制。
  - 提升健壮性（鲁棒性），相对于传统方法， 如果内核出了问题，通常你收到 panic 然后重启，因为，你不能再相信内核里的东西了。如果如果你有一堆用户级别的服务，它们中的一个发生故障，除零操作，或这释放野指针，也许只有那个崩溃，让操作系统的其他部分完好无损，然后也许你只重启它。
  - 可以模拟一个或多个操作系统，在一个微内核上，所以，即使微内核几乎不直接为你做任何事情，你也可以运行 Unix 服务器或其他东西在它上面

但是这些，这些不是微内核方法的必然结果，这些都是人们希望通过使用微内核来实现的。

> 要整一个微内核， 有什么挑战？

- 找到内核系统调用接口，尽可能简单，但必须足够强大，能支持需要做的所有事情，比如exec和fork，直到构造O/S其他部分。
- 这种架构需要大量通过 IPC 进程间通信，是否能足够快，让微内核保持竞争力



## L4 微内核

### 基本介绍

L4 是最早的微内核，从 20 世纪 80 年代开始，但它是早期微内核之一，的相当有代表性的。从高的层面来说，它是一个小内核，它只有 7 个系统调用，反观今天的 Linux ，有300+， 400+系统调用

![截屏2024-09-08 22.31.10](https://tc-1258979383.cos.ap-guangzhou.myqcloud.com/66ddb5542568a.png)



### 基本抽象

- 任务（地址空间）
  - 每个任务可以有多个线程，L4 负责在每个任务中调度多个执行线程，也就是说，将线程作为编程结构化工具，并且它也知道地址空间。

- 线程

  - 每个线程都有一个标识符，我们可以对某个线程进行操作。比如，我想发送一条消息，去发送给另一个线程几个字节

  - 线程的创建：
    - 通过系统调用创建新线程、任务及其地址空间。
      - 如果需要传递内存，可以通过特殊的 IPC 将已准备好的指令或数据映射到新任务的地址空间。
      - IPC 消息还可以指定程序计数器（PC）和堆栈指针，内核根据这些信息启动线程执行

- IPC

- 页映射

### L4的服务——有些是系统调用，有些是IPC

- 创建一个任务/地址空间

- 创建和销毁一个线程

- 通过IPC收发信息（地址是线程ID）

- 中断另外一个地址空间

- 访问设备硬件

- 通过IPC接收设备的中断

  - 某些特权任务可以直接将设备硬件或控制寄存器映射到它们的地址空间，跳过系统调用。

  - L4 微内核对设备（例如磁盘或网卡）本身不了解，但用户级软件可以实现设备驱动，并直接访问设备硬件。

**中断处理与 IPC：**

- 设备驱动可以请求内核打开来自特定设备的中断。
- 当设备发生中断时，L4 将中断转换为 IPC 消息，通知相关任务。
- 设备驱动不仅可以读写设备硬件，还能通过 IPC 消息获知中断发生。

- 

L4内核就是这样，除了这些非常简单的 IPC 之外， 没有其他东西，没有设备驱动程序，没有网络支持， 没有文件系统，L4 本身并不支持 fork exec 之类的功能。如果你需要其他东西的话，你需要提供作为用户级别的服务。

#### 调度

**线程切换**：L4 支持线程切换，L4 执行调度和上下文切换，以便在多个线程中复用单个 CPU。L4 为每个线程、每个任务保存了寄存器，当它执行线程时，执行线程会跳入用户空间，切换页表，所以，那个线程将在用户空间中执行一段时间，定时器中断会在一段时间后触发中断 L4 ，L4 将保存这个任务的线程寄存器到任务中，会将这个线程寄存器保存起来，从循环中选择一个新任务运行，这与 xv6 中的调度循环非常像，直到定时器中断停止或直到这个任务 yield

**页面错误处理**：L4 内核将页面错误转化为 IPC 消息，并通知用户空间的分页任务进行处理。

如果分页任务可实现**懒分配**，如某线程尝试写入未分配的内存，分页任务负责从 L4 分配内存。分页任务通过特殊的 IPC 消息请求内核将新分配的内存映射到出错线程的地址空间。然后，分页任务会发送另一条 IPC 消息，通知恢复该线程的执行。

**写时复制与灵活分页**: L4 微内核通过用户级分页任务实现写时复制等高级内存管理功能，而无需修改内核。

### 缺陷

#### 小众化问题

为了让人们都愿意换微内核。这些项目都会面临着一个更具体的问题，它们将如何得到，它们如何实现与现有应用程序的兼容性，鸿蒙就是个例子，为什么一开始要支持安卓，如果一开始鸿蒙还没有微信应用，那基本就凉凉了，后面因为有国家队撑腰，腰杆子硬了，强制让各大公司开发鸿蒙版，才有了去除安卓支持的底气。

这主要是因为人们不愿意为不明显的性能优势而从现有系统切换过来



#### 性能问题

##### 页表切换问题

在传统的 Linux 系统中，当一个进程调用系统调用时，系统会从用户态切换到内核态。Linux 的设计是为了效率，因此它将整个内核映射到用户态进程的页表中。当系统调用发生时，由于内核已经在用户态的页表中映射，不需要切换页表，这样系统调用的开销就减少了。

L4 微内核的设计与 Linux 不同。当 L4 处理进程间通信（IPC）时，它会强制切换页表，因为 L4 不知道 Linux 内核中的用户进程和内核之间的共享关系。在 L4 中，每个进程有一个独立的页表，系统会切换到与该进程相关联的页表。然而，由于 L4 微内核的设计，页表切换不可避免。为了解决这一问题，作者设计了一种共享内存策略，使每个进程都拥有一个与之关联的内核任务，从而能够根据需要切换页表，尽管效率不如预期。

最终，虽然 L4 微内核在一些嵌入式设备（如智能手机）中得到了广泛应用，但它在工作站和服务器中未能流行不过，微内核系统的一些思想和技术（如虚拟内存、客户端服务器架构和模块化内核）对现代操作系统产生了深远影响。

##### 上下文切换和 IPC 开销

由于微内核的模块化设计，系统调用需要经过多次上下文切换，并通过 IPC 实现不同模块的通信。这会导致比宏内核更多的上下文切换，增加缓存未命中、TLB 刷新等开销，进一步影响性能。

#### 适用性问题

微内核在嵌入式系统（如手机和物联网设备）中得到了更多应用，因为这些系统中的性能要求相对较低，且灵活性更为重要。然而，在通用操作系统领域，微内核的优势并不显著。



### 当前近况

- 微内核主要用在嵌入式计算
  - 微控制器，苹果的”enclave“处理器
  - 运行专用的软件
- 微内核从未在通用计算中广泛应用
  - 没有令人信服的理由让人们从 Linux 等切换过来
- 许多微内核研究中的想法已经被现代 UNIX 系统采纳
  - Mach内核推动了虚拟内存支持的采用
  - 可扩展的内核模块是内核扩展需求的回应
  - IPC和用户级服务已经很常见

# 论文阅读： 微内核性能

## 概要

第一代微内核$\mu$-kernel速度慢，缺乏灵活性，为了验证第二代$\mu$-kernel能否克服局限，，将Linux移植到L4微内核上，并将其与原生的Linux进行比较，AIM基准测试的最大吞吐量，显示比原生的低5%，表明了在微内核之上实现高性能的传统操作系统是可能的。

进一步的实验表明， 系统具有很高的可扩展性，且这些扩展性能良好。甚至实时的内存管理（包括二级缓存分配）都可以在用户级实现，并与 L4Linux 共存。
