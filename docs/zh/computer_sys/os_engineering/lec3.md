### 没有OS（内核）会怎么样？

如果没有操作系统，在这种设计中，应用程序如 `sh`（shell）和 `echo` 直接与硬件（如CPU、RAM和磁盘）交互。这种方式可以非常**高效**和**灵活**，在某些特定情况下甚至是一个不错的选择。然而，没有操作系统最主要的问题是， 缺乏**隔离性**，具体来说：

- 资源隔离：一个应用程序可能占用过多内存，或垄断CPU，或者使用所有的磁盘空间。
  
- 内存隔离：一个应用程序的错误可能会写入另一个应用程序的内存，导致冲突或崩溃。

### 通过系统调用实现隔离

Unix系统调用接口通过限制应用程序来帮助实现隔离，通过对硬件资源进行抽象，操作系统能有效隔离进程和资源使用。示例：

- fork()和进程抽象核心：

  - 操作系统通过进程切换透明地分配CPU核心。

  - 操作系统可强制某个进程放弃CPU的使用权

  - 可以运行比实际CPU核心数量更多的进程。

- exec()/sbrk()和虚拟地址抽象内存：

  - 每个进程拥有其“自己的”内存——即一个独立的地址空间。

  - 操作系统决定将进程放置在内存中的哪个位置。

  - 操作系统限制进程只能使用自己的内存空间。

- 文件抽象磁盘块：

  - 操作系统确保不同进程对磁盘的使用不会产生冲突。

  - 操作系统还执行权限管理，确保进程只能访问它们有权限的资源。

- 管道抽象内存共享：
  - 管道用于抽象进程之间的内存共享，确保共享过程安全受控。

系统调用接口经过精心设计，以实现隔离，同时仍然允许受控的共享和可移植性。隔离性不仅仅是为了避免程序错误，还涉及**安全性**。

### 安全性的考虑

> OS设计者是如何考虑安全性的？

1. 假设用户代码是具有恶意的：
   - 用户代码可能主动尝试突破隔离，获取不应访问的资源。
   - 用户代码可能试图诱骗系统调用，让其执行不安全的操作。
   - 用户代码可能尝试干扰其他程序的运行，破坏系统的稳定性。
2. 假设内核代码是值得信任的：
   - 假设内核开发人员是善意且有能力的，不会故意编写恶意代码。
   - 通常不需要担心内核代码互相攻击或滥用系统资源。
   - 尽管如此，内核中依然会有潜在的漏洞。

因此内核必须对用户交互非常小心，这需要具备安全意识！任何内核中的漏洞都可能被利用为安全攻击。

> 内核如何防御用户代码？

- 硬件级控制：利用硬件功能对用户指令进行控制，防止用户代码执行不应访问的资源或操作。

- 精心设计的系统调用接口与实现：系统调用接口需要经过严格的设计和测试，以防止用户代码通过系统调用执行不安全的操作。

### 通过硬件实现隔离

CPU和内核共同设计，实现了

- 用户/管理员模式
- 虚拟内存

#### 内核/用户模式

- 当运行在内核模式， CPU 可以执行特权指令，比如硬件设备的访问，修改页表等。
  - 设置保护，设置硬件和处理器的各种状态等等。
- 当运行在用户模式， CPU 只能执行非特权指令。非特权指令，比如 add sub ，所有分支指令，

当用户程序试图执行特权指令，处理器不会执行，因为特权指令在用户模式下是不允许的，这会引起控制从用户模式到内核模式，让操作系统获得控制权，如果应用程序有问题，就可以杀掉它。

> 那么谁运行的检查代码，判断是否是内核模式，它们如何知道处于内核模式?

一般在处理器中有一个标志，在处理器中有一个标志位，用户模式使用 1 ，一般 1 是用户模式， 0 是内核模式。所以当处理器解码指令时，检查操作码，如果操作码是特权指令，并且那个位设置为 1 ，就会拒绝指定该指令。比如除零指令，就不允许执行。设置这个标志位的指令当然也是特权指令。

RISC-V 还有第三种模式，称为机器模式，但在一般情况下不需要关注。

#### 虚拟内存

处理器还提供了虚拟内存。处理器提供虚拟内存功能，页表负责将虚拟地址（VA）映射到物理地址（PA）。这限制了用户进程可以使用的内存范围。

操作系统设置页表，使得每个应用程序只能访问属于它的内存，并且无法访问内核的内存。页表只能在特权模式（Supervisor模式）下被修改。

### 系统调用如何工作？

当应用程序运行在用户态，系统调用运行在内核态并且需要管理员模式下。 为了能让应用获取到特权资源，在需要访问特权资源时，通过**系统调用**来请求内核的帮助。在RISC-V中，通过`ecall`指令从用户模式切换到内核模式，执行内核代码中的预定义点，内核接管控制权。ecall 指令接受一个参数，一个数字，所以当用户程序想要将控制权转移到内核，调用 ecall 指令，使用数字 ，这个数字就是应用程序想要访问的系统调用编号。这个指令做的是，进入内核中的一个由内核控制的特定位置

一个示例，如果你调用 fork ，在用户空间调用 fork ，实际上没有直接调用操作系统内核对应的函数，而是调用 ecall ，使用 fork 的系统调用编号，然后进入内核。所以这是一次内核转换，在内核侧，有一个函数 syscall 在 syscall.c 中，每次系统调用都会到这个特定的系统调用函数，系统调用查找数字，然后决定传递给寄存器 a0 的数字，系统调用查找那个寄存器 a0 ，查看是哪个数字。 ecall 指令，确保检查参数或类似的事情，保证不会被骗而做一些坏事。

总的来说，在RISC-V中，通过`ecall`指令从用户模式切换到内核模式，执行内核代码中的预定义点，内核接管控制权。

#### 是否有不需要硬件支持的进程隔离

可以通过强类型编程语言实现进程隔离， 微软的Singularity 操作系统，缺点是限制用户只能使用特定语言和编译器。但是硬件支持的 用户/管理员模式 仍然是主流方案。

#### 宏内核 vs 微内核

对于宏内核来说，内核就是一个单一的巨大的程序，实现了所有的系统调用，Linux、WIndows等主流的OS都是如此。简单说 **内核接口 等于 系统调用接口**
好处：子系统之间的协作比较容易，比如缓存能够被文件系统和虚拟内存共享
坏处：交互比较复杂，容易引发BUG，在内核内部没有隔离，比如设备驱动之间

微内核而言，除了IPC（进程间通信）、内存、进程外无其他系统调用，OS的服务跟普通用户程序一样，比如文件系统，网络，设备驱动等。因此shell打开一个文件，是通过内核往文件服务发送消息实现。
好处： 加强了模块化；限制了内核BUG的杀伤力
坏处：较难获得好的性能

## Xv6

### 概述

Xv6 运行在RISC-V 的CPU上， 需要特定的硬件设备叫 "SiFive HiFive Unleashed" 板，配置如下：

- RISC-V 处理器，4 个核心
  - 每个核心有 32 个寄存器、ALU、MMU、控制寄存器、计时器、总线接口等，核心之间共享 RAM 和设备。
  - 共享RAM、和板上设备
- 128MB RAM
- UART 用于控制台
- 磁盘式存储
- 以太网

Qemu 模拟该 CPU 和类似的硬件设备（如使用 `qemu -machine virt` 模拟 "virt" 板），https://github.com/riscv/riscv-qemu/wiki，非常接近Sifive开发板，但是磁盘用的是virtio

xv6 内核代码结构简单，比如文件系统位于 `kernel/fs.c` 中。在kernei/defs.h可以看到所有的模块和内部接口。可以通过 `make` 来构建整个内核，生成内核二进制文件和磁盘镜像（`fs.img`）。

#### Qemu作用

- 使用 Qemu 模拟器将内核二进制文件加载到"内存中"，用``fs.img``模拟磁盘，
- Qemu 会将内核的第一条指令加载到模拟的内存中。
- Qemu 维护仿硬件寄存器、RAM和中断指令



### xv6 启动过程

1. xv6 启动时，内核会加载到 0x80000000 地址（因为该地址是 RAM 的起始位置）。

   ```
   (gdb) b *0x80000000
   (gdb) c
   ```

2. 此时内核实在机器模式下（M模式），第一条指令会跳转到 `entry.S` 中定义的 `_entry` 标签。这个标签下的指令，设置栈并跳转到 C 代码中的 `start()` 函数。

   - 具体实现在``start.c``

3. `start()` 函数完成硬件初始化并切换到管理员模式，然后跳转到 `main()` 函数。

4. ``main()``函数里面，core 0设置了软件其他核则是等待

   ```
   (gdb) b main
   (gdb) c
   (gdb) tui enable # ext User Interface (TUI) 模式
   ```

   在 TUI 模式下，屏幕分为多个区域，可以同时显示源代码、寄存器和汇编代码（如果需要）、调试命令行。

   #### TUI视图常见操作

   - `layout src`（显示源代码窗口）
   - `layout asm`（显示反汇编窗口）
   - `layout split`（分屏显示源代码和汇编）
   - `layout regs`（显示寄存器窗口）
   
   #### **TUI 视图常见快捷键：**
   
   - `Ctrl-x 1`（仅显示代码窗口）
   
   - `Ctrl + L`：刷新屏幕。
   - `Ctrl + P / Ctrl + N`：在历史命令中导航。
   - `Ctrl + x s`：切换布局（源码视图、汇编视图等）。

#### 内存初始化

内核的内存分配器在启动时会通过 `kinit()` 和 `freerange()` 找到所有的物理内存页并将它们加入到一个链表中，每个内存页以 4096 字节的单位进行分配。

```
(gdb) b userinit
(gdb) c

```



#### 进程启动

启动第一个用户级程序 `init`（``user/init.c``），该程序会启动所有其他进程（比如 xv6 中的控制台 shell）。通过 `allocproc()` 函数为进程分配内存、创建页表，并设置进程的状态为可运行 

#### 系统调用的执行：

进程通过系统调用（如 `exec()`）来启动其他程序。`ecall` 指令触发系统调用，内核通过读取用户寄存器中的值（如 `a7`）来判断调用的具体系统调用号，并跳转到对应的内核处理函数中。

```
(gdb) b *0x0
(gdb) c
(gdb) tui disable
(gdb) x/10i 0

what's the effect of ecall?
(gdb) b syscall
(gdb) c
back in the kernel
(gdb) tui enable
(gdb) n
(gdb) n
(gdb) n
(gdb) print num
      from saved user register a7
(gdb) print syscalls[7]
(gdb) b exec
(gdb) c 
```



#### ELF 格式的执行：

`exec()` 系统调用会从磁盘读取 ELF 格式的可执行文件，并将代码和数据加载到用户空间的内存中，同时为进程分配堆栈并设置入口点（epc，即程序计数器）和新栈起始指针（sp）
