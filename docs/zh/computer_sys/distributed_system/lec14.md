# 论文阅读： FaRM

[FaRM(2015)](https://pdos.csail.mit.edu/6.5840/papers/farm-2015.pdf)， 全程 Fast Remote Memory

## 摘要

具有强一致性和高可用性的事务能简化了分布式系统的构建和推理。但是之前的实现效果不佳，迫使系统设计人员避免事务，削弱一致性的保证，或者需要程序员自行实现数据分片（系统不自动帮你了）。本文论证了在现代数据中心环境中已无需此类妥协。我们通过新型内存分布式计算平台FaRM证明：分布式事务可实现严格序列化、高性能运行、持久化保证及高可用性。FaRM在90台服务器组成的集群中处理4.9TB数据库时，TATP基准测试峰值吞吐量达1.4亿次事务/秒，且故障恢复时间低于50毫秒。取得这一突破的关键在于：我们基于RDMA商用网络与新型低成本非易失性内存技术，从**第一性原理**出发重新设计了事务处理、数据复制及故障恢复协议。



## 1. 介绍

这样的抽象可以简化分布式系统的编程和推理： **一台永不故障且某个时间点只执行一个事务的单机**。这种抽象的实现往往性能不佳。FaRM 提供分布式 ACID 事务，具有严格的序列化、高可用性、高吞吐量和低延迟。这些协议的设计基于两大硬件趋势的假设：1. 远程DMA技术（Remote Direct memory access）——一种网络技术，允许一台计算机直接访问另外一台计算机的内存，无需对方CPU参与。2. 一种低成本的提供非易失性DRAM——断电后数据不会丢失的内存——通过UPS（Uninterruptable Power Supplies）保障故障时将 DRAM 的内容写入 SSD 来实现的。 这两个趋势消除了存储和网络瓶颈，但也暴露了新的瓶颈——CPU。 FaRM的协议遵循三个原则来解决这些CPU瓶颈：

- 减少消息数量
- 用one-sided RDMA读写代替消息
- 有效利用并行性

**扩展性设计** 将数据对象分布在多台机器实现水平扩展，同时允许事务跨越任意数量的机器。FaRM采用乐观并发控制机制，并使用四阶段提交协议（锁定、验证、提交到备节点、提交到备节点），但我们改进了该协议，在锁定阶段去除了发送给备节点的额外消息。FaRM还通过使用单边RDMA操作进一步降低CPU开销。

**容错设计** 使用单向RDMA需要新的故障恢复协议。例如，FaRM无法依赖服务器在租约过期时拒绝接收请求，因为请求是由网卡处理的，而网卡不支持租约机制。

## 3. 编程模型和架构

![image-20250918153415800](https://tc-1258979383.cos.ap-guangzhou.myqcloud.com/image-20250918153415800.png)

FaRM为应用程序提供了一个跨集群所有机器的全局地址空间抽象。每个机器运行应用程序线程，并在该地址空间中存储对象。 FaRM API支持事务中对本地和远程对象的透明访问。应用程序线程可以随时启动事务，并成为该事务的协调器。在事务执行期间，线程可以执行任意逻辑，以及读取、写入、分配和释放对象。事务执行结束后，线程调用FaRM提交事务。

FaRM事务采用乐观并发控制。在事务执行期间，更新数据缓存在本地，只有在事务成功提交后才对其他事务可见。由于与并发事务冲突或系统故障，提交可能会失败。FaRM保证所有成功提交的事务具有严格的线性一致性。在事务执行期间，FaRM保证对单个对象的读取是原子操作，只读取已提交的数据，对同一对象的连续读取返回相同的数据，以及对事务写入的对象读取时返回最新的写入值。它不保证对不同对象的读取操作的原子性，但它保证事务不会提交，从而确保已提交的事务具有严格的序列化一致性。这使得我们可以在提交时进行一致性检查，而不是在每次读取对象时都进行一致性检查。然而，这增加了编程复杂度：FaRM应用程序必须在执行期间处理这些临时不一致性[20]。也可以自动处理这些不一致性（重试？）[12]。

FaRM API还提供无锁读取，这是一种针对单个对象读取优化的事务，以及位置提示，允许程序员将相关对象放置在同一组机器上。应用程序可以利用这些特性来提升性能。
